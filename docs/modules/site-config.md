### 1.2 不做的事

| 不做 | 理由 |
|---|---|
| 多租戶、讓別人註冊開店 | 用戶選 C |
| 自由填 CSS、HTML、JavaScript；上傳 SVG | 等於讓後台帳號寫進 stored XSS（security-baseline §0 #2）。圖示從內建圖示庫挑，或上傳 PNG／WebP |
| 拖拉式頁面編輯器 | 維護成本是整個專案的好幾倍，也會破壞 §B0 的版面規則。改成固定區塊的開關與排序（G5） |
| 外部字型 | §B0 與守衛 `no-google-font` |
| 改按鈕、錯誤訊息這類介面文字 | 同一個動作的名稱要全站一致（§A9）；開放修改後，一處改了、別處沒改就會不一致（OQ-CFG-5） |
| 把資安、權限、R11「不能下單」、上傳驗證、個資保留期做成設定 | 放進設定等於讓後台帳號可以關掉它們 |

## 4. 設計

### 4.1 商品欄位：屬性庫（C1，⏳ 待 review）

**做法**：商品只保留每種商品都有的欄位；其他欄位改成後台定義的「屬性」。

| 留在 `Product` 的通用欄位 | 改成屬性的（目前寫死） |
|---|---|
| 分類、狀態、品名（`name`）、價格、圖片、產品訊息（條列）、特色（條列）、規格表（標籤／值列）、規格補充、收購來源（只在後台可見）、時間戳 | 品牌、型號、英文品名、年份、狀況、保固、醫療器材許可證字號，以及之後任何新欄位 |

```prisma
// 全站屬性庫：同一個「品牌」屬性可以給很多分類用，品牌篩選才能跨分類
model AttributeDef {
  id          String        @id @default(cuid())
  key         String        @unique   // 建立後不能改（商品資料用它當鍵）；^[a-z][a-z0-9_]{0,31}$
  label       String        // 可改，≤ 30
  type        AttributeType // TEXT | NUMBER | YEAR | SELECT
  options     String[]      // SELECT 才用，≤ 50 個，每個 ≤ 30
  unit        String?       // 例：「年」「kg」
  maxLength   Int?          // TEXT 用，預設 80
  categories  CategoryAttribute[]
}

// 分類挑哪些屬性、怎麼顯示
model CategoryAttribute {
  categoryId  String
  attributeId String
  sortOrder   Int
  required    Boolean   // 上架時必填（存草稿不檢查，同 catalog.md §4.3）
  inTitle     Boolean   // 參與標題組合（取代 OQ-CAT-1 的固定規則）
  onCard      Boolean   // 顯示在商品卡的副標行（例：2019 年・良好・保固三個月）
  inNameplate Boolean   // 顯示在商品頁銘牌
  filterable  Boolean   // 列表頁可篩選（只限 SELECT、YEAR、NUMBER）
  @@id([categoryId, attributeId])
}

model Product {
  // …通用欄位同 catalog.md §4.1，拿掉 brand / model / nameEn / condition / warranty / licenseNo
  attributes  Json      // { "brand": "GE", "year": 2019, "condition": "良好" }
}
```

- **寫入驗證**：伺服器依「這個分類的屬性定義」動態產生 zod schema 來驗 `attributes`，不認識的鍵直接拒絕，型別錯了也拒絕。前端驗證只是方便，不算數。
- **篩選與搜尋**：`attributes` 加 GIN index（migration 手寫 SQL）。關鍵字搜尋涵蓋品名＋所有 TEXT 屬性值。
- **改定義時的規則**：
  - `key` 永遠不能改，`label` 可以改；
  - 屬性已有商品使用時，不能改 `type`，也不能刪除（要先在所有分類取消勾選，並清空值）；
  - SELECT 選項可以新增；刪除選項時，如果有商品正在用，就擋下並列出是哪些商品。
- **分類換掉時**：商品從 A 分類移到 B 分類，B 沒有的屬性值保留但不顯示，後台標示「這些欄位在新分類沒有」。
- **預設資料（seed）**：本公司現有的設備欄位變成第一批屬性，前台看起來跟現在的 mockup 一樣：品牌、型號、英文品名（TEXT）、年份（YEAR）、狀況（SELECT：近新／良好／堪用）、保固（TEXT）、醫療器材許可證字號（TEXT，只勾給醫療類分類）。
- **R11③** 從「許可證是選填欄位」變成「許可證是只勾給醫療類分類的選填屬性」，意思不變。
- **為什麼不用 EAV（每個值一列）**：列表頁每張卡要讀 3–4 個屬性，EAV 要多一次 join 或多一次查詢，直接撞上 query 預算（≤ 5）；JSON 一次就讀回來。代價是要靠應用層驗證型別（上面的動態 zod），以及手寫 GIN index（OQ-CFG-1）。

### 4.2 站台設定的儲存（C2）

```prisma
// 每一區一份 JSON 文件，各自有 zod schema 和版本號
model SiteConfig {
  section    ConfigSection  @id   // PROFILE | THEME | HOME | COPY | FEATURES
  value      Json
  version    Int                  // 樂觀鎖：存檔帶舊版號，不一致就擋（兩個人同時改）
  updatedAt  DateTime @updatedAt
  updatedBy  String
}

model SiteAsset {             // 站台用的圖片（首頁照、看機區照、品牌 logo、logo、favicon）
  id         String   @id @default(cuid())
  kind       AssetKind          // LOGO | FAVICON | HERO | VISIT | BRAND_LOGO
  storageKey String
  width      Int
  height     Int
  alt        String?
  sortOrder  Int
}
```

- 為什麼一區一份 JSON，而不是一個欄位一欄：設定項目會一直加，每加一項就要一次 migration 不划算。用 zod schema 管版本，讀取時用 `schema.parse`，缺的欄位補預設值，舊資料不會讓頁面掛掉（memory pitfall「嚴格 schema 一壞炸整個 list」）。
- 圖片走 catalog A2 的同一條管線（只收 JPEG／PNG／WebP、重新編碼、去 EXIF）。

### 4.3 主題（G4）

後台只選 **2 個顏色＋1 個圓角檔位**，其餘全部自動推導：

| 後台選 | 自動推導 |
|---|---|
| 主色 | 深底（主色加深）、淺底（主色加淡）、連結色 |
| 重點色 | 重點淡底 |
| 圓角：小 4／中 6／大 10 | Tag、搜尋卡的圓角 |

- **存檔時擋對比**：把 `tokens.test.ts` 的 AA 檢查（≥ 4.5:1）搬成伺服器端函式。主色上的白字、白底上的主色字、重點色上的白字、白底上的重點色價格，任一組不及格就擋下，並寫明是哪一組、差多少。
- ⚠️ **M2 要補**（2026-11-01 mockup 時發現）：上面 4 組只檢查主色、重點色本身。推導出的淡底（主色字在主色淡底上＝後台選單選中項、重點色字在重點淡底上＝「已在清單」按鈕）沒有檢查。4 組預設都及格，但自訂顏色剛好過 4.5:1 時，放到淡底上可能不及格。做法二選一：把這兩組加進存檔檢查，或依需要的對比反推淡底。
- **預設配色組**：「實機型錄（藍＋橘）」＝目前的 §B0，另外再給 3–4 組，都事先通過對比檢查。
- `tokens.ts` 的常數變成「預設值＋推導函式」；守衛 `no-hardcoded-hex` 不變。
- §B0 的其他規則不變：不用漸層、版面、商品卡順序、照片規範。

### 4.4 首頁區塊（G5）

固定的區塊類型，只能開關與排序：首屏、分類、最新上架、品牌、怎麼買＋看機地點、服務、頁尾（頁尾不能關）。首屏不能關，也不能移到第一個以外的位置，因為 §B0 規定唯一的搜尋在首屏。

### 4.5 文案（G6）

可以改的文案在後台用表單編輯，**留空就用程式碼裡的預設值**（`src/copy/`）：首屏小標、標題（最多 2 行）、三句承諾、怎麼買三步驟（標題＋說明）、服務三項、頁尾一句話。

- **療效字詞守衛**同樣適用（R11②）：存檔時警告並寫 audit。
- 長度上限依版面訂，例如標題每行 ≤ 16 字，超過就擋，避免版面爆掉。

### 4.5-bis 店家說明選項（v0.3，用戶 2026-11-01）

> 用戶：「前台那幾句服務說明，預設不用加，在管理後台設定即可，做成可靈活使用的『選項』。」

保固、發票、到場拆裝運送、收購／維修／租賃、「自有庫存 · 可預約看機」這類句子是**店家的事實宣稱**，程式碼不能替店家預設。它們從 §4.5「留空用預設值」移出，改成**留空就不顯示**：

| 位置 | 資料（`SiteConfig` COPY，`src/modules/site-config/notes.ts`） | 上限 | 沒設定時 |
|---|---|---|---|
| 首屏小標 | `eyebrow` | 30 字 | 不顯示 |
| 首屏重點 | `heroPoints[]` | 3 項 × 20 字 | 不顯示 |
| 商品頁「保固與交易說明」 | `terms[]` | 8 項 × 120 字 | 整區不顯示 |
| 首頁「也可以找我們」 | `services[]`：`kind`（收購／維修／租賃／其他，只決定圖示）、`title` ≤ 10、`body` ≤ 40 | 4 項 | 整區不顯示 |

- 項目數量、文字、順序都由後台決定，所以 §4.6 的「收購、維修、租賃」開關不再需要：沒有項目就不顯示。

- 「怎麼買」第三步原本寫「大型設備派人到場拆裝，運費另計」，預設改成「成交：確認設備狀況後再付款成交。」。

- ⏳ 後台編輯畫面隨 C4 站台設定一起做；存檔照 §4.5 走療效字詞守衛和 audit。後台站台設定 mockup 裡的收購／維修／租賃三個開關（`adminCopy` `servicesAllOff` 等）已過時，C4 時改成清單編輯。

### 4.7 讀取與快取（C3）

- 前台每頁都會讀設定，所以走 `'use cache'`＋`cacheTag('site-config')`，後台存檔後 `revalidateTag`，**存檔即生效**。
- ⚠️ stack-rules P7-1 規定 `'use cache'` 只能用在 `src/modules/catalog/server/public/`。設定的公開讀取放在新的 `src/modules/site-config/server/public/`，需要**修改 P7-1 的白名單**（同一個 commit 改規則和守衛 `cache.sh`）。設定是公開資料，沒有身分維度，加進白名單的條件跟 catalog public 一樣。
- 後台讀設定不用快取（P7-1 原規則）。

## 7-bis. cross-cutting 檢核（Mode B）

| 面向 | 內容 |
|---|---|
| **安全** | 所有設定寫入走 `requireAdmin()`＋audit（記 section、前後差異）。不收 SVG、HTML、CSS。地圖用外部連結，**不嵌 iframe**（不必放寬 CSP）。屬性 `key` 用 regex 鎖住；`attributes` 的 JSON 鍵只接受已定義的 key（避免拿 JSON 塞任意資料） |
| **效能** | 設定每頁讀一次，走快取，不增加 DB query。列表頁的屬性篩選用 GIN index；整合測試量 query 數（列表 ≤ 5，§0 預算不變） |
| **失效** | 設定 JSON 壞掉或缺欄位時，`schema.parse` 補預設值並記 log，**前台不掛**。主題對比不及格的存檔擋在後台，前台永遠不會用到不及格的配色 |
| **觀測** | audit 就是設定的變更歷史；「還原上一版」直接讀 audit 裡的前一份 value（OQ-CFG-6） |
| **兼容** | 還沒有 migration，C1 跟 catalog M1 同一批 schema，沒有舊資料要搬 |
| **成本** | 不新增外部服務；SiteAsset 只有十幾張圖 |

## 8. 測試策略

| 層級 | 覆蓋 |
|---|---|
| Unit | 動態 zod：未定義的鍵、型別錯、SELECT 不在選項內、必填缺漏都拒絕；顏色推導＋對比檢查（陽性：預設組全過；陰性：淺黃主色要被擋）；設定 schema 缺欄位時補預設值 |
| Integration | 屬性有商品在用時不能刪、不能改型別；兩人同時存設定，後到的被樂觀鎖擋下；`revalidateTag` 後前台讀到新值；列表屬性篩選的 query 數 |
| E2E | 後台改主色 → 前台按鈕變色；關掉「顯示價格」→ 卡片顯示「歡迎詢價」；新增「尺寸」屬性勾給某分類 → 商品表單出現該欄位 → 商品頁銘牌出現；首頁關掉品牌區 → 前台不見 |

## 12. 失效場景反思（FMEA）— 收尾必填（R17）

> M4 時逐路徑補齊。目前已知的：

| 失效 | 影響 | 嚴重度 | 緩解 |
|---|---|---|---|
| 設定 JSON 壞掉，前台整站掛掉 | 全站停擺 | P0 | 讀取時 `schema.parse` 補預設值，絕不拋錯到頁面（§7-bis 失效） |
| 刪掉一個商品正在用的屬性或選項 | 商品資料遺失 | P0 | 有商品在用時擋下並列出商品（§4.1） |
| 主色調成看不清楚的顏色 | 全站可讀性崩壞、a11y 不合格 | P1 | 存檔時對比檢查擋下（§4.3） |
| 存檔後前台還是舊設定 | 改了以為沒生效，重複操作 | P1 | `revalidateTag`；整合測試驗證 |
| 兩人同時改設定，後存的蓋掉先存的 | 設定被默默覆蓋 | P2 | ✅ 樂觀鎖（`version`）；兩人同時第一次存，第二個撞主鍵也回 CONFLICT；e2e 兩個分頁同時存 |
| 存檔後前台還是舊設定（實測） | 同上 | P1 | ✅ `updateTag('site-config')`；e2e 存檔後直接開前台檢查電話、說明出現，還原後消失 |
| 某一項說明資料壞掉 | 整個清單不顯示 | P2 | ✅ 讀取逐項驗證，只丟壞的那一項（`notes.test.ts`） |
| 電話欄位存了非電話字串 | `tel:` 連結撥不出去 | P2 | ✅ 伺服器端只收數字、空白和 `+ - ( ) #`，錯誤顯示在欄位下 |
| 「還原上一版」在設定列被刪掉後還原到很久以前的值 | 還原結果出乎意料 | P2 | ⚠️ 殘留：只有 e2e 會刪 `SiteConfig`（teardown），正式環境沒有刪除路徑 |
| audit 記了整份店家資料 | audit 有個資 | P2 | ✅ 存的是店家公開聯絡方式（前台本來就顯示），不是買家個資；買家個資仍不進 audit |
