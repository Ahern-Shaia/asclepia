## 2. 每頁做了什麼

**列表**
- 左側篩選欄：分類（附件數），再加上「可篩選」的商品欄位。目前是品牌、年份、狀況，由後台「商品欄位」決定，程式裡沒有寫死。
- 篩選、排序、關鍵字都寫在網址上，網址可以直接分享。
- 平板和手機的篩選收進底部抽屜，底下按鈕寫「看 N 件」。
- 卡片欄數：桌機 4、平板 3、手機 2（§B0）。

**商品頁**
- 標題用分類勾了「組進標題」的欄位組成（品牌 型號），下面一行是品名。
- 銘牌顯示勾了「顯示在銘牌」的欄位。醫療器材許可證字號只勾給醫療類分類，所以顯微鏡（p5）沒有這一列。
- 按鈕：
  - 「詢價這件」：橘色主按鈕，直接開表單，只含這一件。
  - 「加入詢價清單」。
  - 「預約看機」（來電）。
- 已售出：沒有詢價按鈕，價格加刪除線，留一句來電問同型號。

**詢價清單**
- 清單存在瀏覽器裡（OQ-INQ-1），最多 10 件（OQ-INQ-4）。
- 清單裡有已售出的商品時，整筆擋下，並寫出是哪一件（OQ-INQ-5）。
- 送出成功後清單清空，成功頁列出問了哪幾件。
- 瀏覽器不能保存清單時（無痕模式等）會顯示一句說明。
- 不顯示合計、沒有數量欄位（R11①）。

**後台・站台設定**
- 5 個分頁：店家資料、主題、首頁區塊、文案、功能開關。每頁底下都有「儲存」「還原上一版」「上次儲存：時間・誰」。
- **主題**：
  - 可以選 4 組預設配色，或自訂主色、重點色，圓角分小、中、大。
  - 有即時預覽和 4 組對比檢查。不及格時存檔按鈕停用，並寫明哪一組、對比多少。
- **文案**：留空就用預設文字。超過字數不能存。打到療效字詞（例如「改善」）會跳警告。

**後台・商品欄位**
- **欄位庫**：代號建立後不能改。有商品在用的欄位，不能刪、不能改類型，按鈕旁寫有幾件在用。
- **各分類設定**：6 個勾選項，右邊即時預覽卡片和銘牌。文字欄位不能設成可篩選。

## 3. 驗證（2026-11-01）

- **前台**：正式建置（`pnpm build` 後用 `ENABLE_MOCKUPS=1 pnpm start`），用 Playwright 在 1440、900、390 三種寬度實際操作，三種寬度結果一致：
  - 首頁加入 1 件，到列表頁件數還在。
  - 勾「GE」後網址帶 `f.brand=GE`，結果剩 1 件。
  - `q=MRI` 顯示空狀態。
  - 價格低到高排序正確，「歡迎詢價」排最後。
  - 商品頁：
    - 銘牌欄位正確（p1 有許可證、p5 沒有）。
    - 「詢價這件」空白送出列出 3 個錯誤，填好後顯示「已收到你的詢價（1 件）」。
    - 已售出的商品頁沒有詢價按鈕。
  - 詢價清單：2 件送出成功後件數歸 0；`demo=sold` 送出鈕停用並寫明是哪一件。
  - 每頁都已 hydrate、沒有橫向捲動、只有 1 個 `h1`、MOCKUP 橫幅 1 個、console 錯誤 0。
- **後台**：agent 用 Playwright 驗證 39/39 通過（1440、390）。
- **全套**：`pnpm check`（31 個單元測試、守衛 9/9、build）＋ `pnpm test:e2e` 16/16。

**驗證時踩到的兩件事**（都和 dev 或量測環境有關，不是頁面問題）：
1. dev server 一直用舊版文案在伺服器端渲染，造成 hydration 錯誤，touch 檔案也沒用。改用正式建置驗證後，錯誤 0。
2. `pkill -f "next start -p 3300"` 沒命中實際行程名（`next-server`），舊的正式版 server 還在跑，第一次重跑時拿到舊頁面。改用 `lsof -tiTCP:3300` 找行程。
